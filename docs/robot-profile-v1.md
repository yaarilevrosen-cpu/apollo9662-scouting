# פרופיל רובוט לסימולטור – מבנה גרסה 1

לפי החלטה 04. הסקאוטינג (04) בונה, הסימולטור (03) קורא בלבד ומתרגם לבוטים שלו.

- יחידות: שניות, אינצ׳ים, וחלקים בין 0 ל־1 (לא אחוזים).
- הקובץ נוצר אצל המנהל, בכפתור "ייצוא לסימולטור" במסך ההגדרות, ונשאר במחשב המקומי.
- נתונים על קבוצות אמיתיות לא נכנסים לשום מאגר. הדוגמאות כאן עם מספרים דמיוניים, ונוצרות מהבדיקות האוטומטיות (לא בעריכה ידנית): `docs/samples/sim-match-sample.json`, `docs/samples/sim-event-sample.json`.
- סכמה לבדיקה אוטומטית: `docs/robot-profile-v1.schema.json`.
- הצעה לסימולטור: להוסיף `sim-*.json` לרשימת הקבצים שלא נכנסים למאגר.

## שני סוגי קבצים

| `format` | מה יש בו |
| --- | --- |
| `apollo9662-scouting/match` | `match`, `alliances` (`red`, `blue`: שתי קבוצות בכל אחת), `robots`: ארבעה פרופילים, לכל אחד `alliance` |
| `apollo9662-scouting/event` | `schedule` (מספר מאץ׳ → `{ red: [..], blue: [..] }`, רק מאצ׳ים מלאים), `robots`: כל הקבוצות |

שדות משותפים: `version` (כרגע 1), `generated_at`, `event`, `event_code`, `units`.

## פרופיל רובוט

| שדה | משמעות |
| --- | --- |
| `team` | מספר קבוצה |
| `matches_seen`, `no_shows` | כמה מאצ׳ים נסקרו, וכמה פעמים לא הגיע |
| `confidence` | ביטחון כללי, 0 עד 1 (5 מאצ׳ים ומעלה = 1) |
| `is_us` | הרובוט שלנו. את המצב האמיתי שלו הסימולטור יקבל בנפרד |
| `declared` | מה שהקבוצה סיפרה בפיט, או `null` |
| `measured` | מה שנמדד במאצ׳ים, או `null` |

### `declared` (מהפיט)

כל ערך שהסקאוטר לא שאל עליו הוא `null` – גם כן/לא, גם מספרים וגם רשימות. `null` = לא ידוע, לא "לא". `confidence` קבוע: 0.5, כי זה מה שהקבוצה מספרת על עצמה. כשכמה סקאוטרים מילאו, כל שדה נלקח מהרשומה האחרונה שענתה עליו, ורשימות מאוחדות.

| שדה | ערכים |
| --- | --- |
| `drive` | `mecanum`, `tank`, `other` |
| `speed` | `slow`, `mid`, `fast` |
| `capacity` | 1–4 כדורים |
| `intake_from` | רשימה: `flower`, `floor`, `human` |
| `intake_side` | `front`, `back`, `side` |
| `shooters` | 0, 1, 2 |
| `shooter_mount` | `fixed`, `turret` |
| `shooter_wheels` | `one`, `two`, `other` – כמה גלגלים מעיפים את הכדור, לא כמה יורים |
| `max_range_in` | 36, 72, 108, 144 (כל הזירה) |
| `shoot_zones` | רשימה: `near`, `mid`, `far` |
| `shoots_moving`, `auto_aim` | כן או לא |
| `auto_starts` | רשימה: `A`, `B`, `C` (בכחול D, E, F) |
| `auto_leave`, `auto_park` | כן או לא |
| `auto_balls`, `auto_tips`, `auto_programs` | מספרים |
| `end_park`, `late_nectar`, `flower_lift`, `full_size` | כן או לא |
| `preferred_role` | `scorer`, `defense`, `both` |


### `measured` (מהמאצ׳ים)

כל ערך הוא `{ value, confidence, n }`, או `null` כשאין נתונים. `n` = על כמה מאצ׳ים הוא מבוסס. ברירת המחדל לביטחון: `n` חלקי 5, עד 1. חריגים: `accuracy` – מספר היריות חלקי 30; `cycle_s` – מספר המרווחים חלקי 10.

קבוצה שלא הגיעה לאף מאץ׳ מקבלת רק `reliability` עם 0.

כמה סקאוטרים על אותו רובוט ומאץ׳: חציון לכל מספר. "לא הגיע" לא מתערבב עם רשומה של רובוט ששיחק (מנצח הרוב, ובשוויון – ששיחק). דירוג נהיגה ויריות נלקחים רק ממי שמילא. עמדת פתיחה ואזור ירי – הרוב, ובשוויון הרשומה החדשה.

| שדה | יחידה |
| --- | --- |
| `cycle_s` | חציון השניות בין היפוכים בדקה הראשונה של השליטה הידנית (שניות 38 עד 98). בין היפוכים, לא בין יריות |
| `tips_per_match` | כל ההיפוכים למאץ׳, כולל אוטונומי |
| `auto_tips` | היפוכים באוטונומי למאץ׳ |
| `accuracy` | כל הפגיעות חלקי כל היריות, בכל המאצ׳ים יחד, 0–1 |
| `shots_per_match` | יריות למאץ׳ (פגיעות והחטאות), רק במאצ׳ים שבהם הטופס כבר ספר יריות, כולל מאצ׳ים עם 0 |
| `auto_points`, `tele_points`, `end_points`, `total_points` | ממוצע נקודות למאץ׳, בלי תיקון. `total_points` = סכום השלושה (עד הפרש עיגול של 0.1) |
| `auto_start` | `A`, `B`, `C` – הנפוצה ביותר. העמדות כמו במדריך התחרות; בצד הכחול אותה עמדה נקראת D, E, F |
| `main_shoot_zone` | `near`, `mid`, `far` – הנפוץ ביותר |
| `auto_leave`, `auto_park`, `end_park` | חלק מהמאצ׳ים, 0–1 |
| `defense_share` | חלק הזמן בהגנה, 0–1 ("חלק" = 0.5, "רוב הזמן" = 1) |
| `reliability` | 1 פחות חלק המאצ׳ים שבהם נתקע או לא הגיע |
| `fouls_points_per_match` | נקודות שנתן ליריב בעבירות |
| `drive_rating` | איכות נהיגה, 0–1 |

## מה עוד אין בגרסה 1

- זמן האוטונומי, וכמה כדורים נורו באוטונומי בפועל (יש רק את מה שהוצהר בפיט).
- זמן בין יריות (יש רק זמן בין היפוכים).
- המרחק באינצ׳ים של קרוב, אמצע ורחוק.

## שינויים במבנה

- קורא שמקבל `version` שהוא לא מכיר – דוחה את הקובץ.
- שדה שהקורא לא מכיר – מתעלם ממנו. הוספת שדה או ערך חדש לרשימה לא מעלה גרסה.
- הסרת שדה או שינוי משמעות – מעלה את `version`.
