# הקמת הענן של הסקאוטינג – צעד אחר צעד

פעם אחת, בערך 15 דקות. צריך חשבון סופאבייס (אפשר עם אותו מייל של הסימולטור, אבל **פרויקט חדש ונפרד** – החלטה 01: הנתונים שייכים ל־04).

## 1. פרויקט חדש

1. נכנסים ל־supabase.com ← New project. שם: `apollo9662-scouting`. אזור: הכי קרוב (פרנקפורט).
2. שומרים את סיסמת מסד הנתונים במקום בטוח. היא לא נכנסת לשום קובץ.

## 2. המבנה וההרשאות

1. SQL Editor ← New query.
2. מדביקים את כל `supabase/schema.sql` ומריצים.
3. אמור להיגמר בלי שגיאות. אפשר להריץ שוב בלי נזק.

## 3. כניסות

1. Authentication ← Sign In / Providers:
   - **Anonymous sign-ins: להפעיל.** כך סקאוטרים נכנסים רק עם קוד הקבוצה, בלי מייל.
   - Email: להשאיר פעיל, עם **Confirm email** דלוק. בו נכנסים המנהל והסימולטור.
   - Attack Protection: להפעיל CAPTCHA (Turnstile) – מגן על כניסה אנונימית מבוטים.
2. Authentication ← Users ← Add user:
   - המנהל: המייל של יערי וסיסמה ארוכה. לסמן Auto Confirm. מומלץ להפעיל אימות דו־שלבי.
   - הסימולטור: מייל נפרד (למשל כתובת משנית) וסיסמה. לסמן Auto Confirm.
3. מעתיקים את ה־User UID של כל אחד, ומריצים ב־SQL Editor:

```sql
insert into members(uid, role, name) values
  ('<UID של המנהל>', 'manager', 'יערי'),
  ('<UID של הסימולטור>', 'reader', 'סימולטור');
insert into settings(key, value) values ('join_code', '<קוד לסקאוטרים: לפחות 8 תווים אקראיים, למשל 10 אותיות ומספרים>')
  on conflict (key) do update set value = excluded.value;
```

## 4. זמן אמת

Database ← Publications ← `supabase_realtime`: לוודא ש־`docs`, `sim_profiles`, `sim_meta` מסומנות. (הקובץ מנסה לסמן לבד.)

## 5. לחבר את האפליקציה

1. Project Settings ← API: מעתיקים את **Project URL** ואת המפתח **anon public**.
2. ממלאים ב־`app/config.js`. המפתח הזה ציבורי ומותר בקוד (החלטה 03). **את ה־service_role לא מעתיקים לשום מקום.**
3. דוחפים למאגר. הפעולה בגיטהאב בונה את האתר ומעלה אותו.

## 6. האתר

1. במאגר בגיטהאב: Settings ← Pages ← Source: **GitHub Actions**.
2. אחרי הדחיפה, הכתובת מופיעה שם. זה הקישור לסקאוטרים.

## 7. לסימולטור

שולחים לבוט של 03, **בערוץ פרטי ולא במסמך משותף**: הכתובת, המפתח הציבורי, והמייל והסיסמה של חשבון הסימולטור. הוא שומר אותם בקובץ הגדרות מקומי שלא נכנס למאגר שלו. החשבון הזה קורא רק את הפרופילים.

## אבטחה – מה חשוב לדעת

- קוד ההצטרפות הוא מה שמפריד בין הצוות לבין כל מי שיש לו את הקישור. ארוך ואקראי, ומחליפים אחרי תחרות.
- אחרי 5 ניסיונות שגויים בעשר דקות – הכניסה נחסמת לאותו חשבון.
- סקאוטר שעזב: מסך ההגדרות ← "סקאוטרים שהצטרפו" ← הסר. הרשומות שלו נמחקות ולא נספרות יותר.
- טלפון משותף: בסוף, "התנתק" בלשונית הפרופיל. ההתנתקות לא מוחקת רשומות שעוד לא נשלחו.

## בדיקה מהירה

- סקאוטר: פותח את האתר, שם + קוד → נכנס.
- מנהל: "כניסת מנהל" → רואה את לשונית ההגדרות. בקטע "קובץ לסימולטור" רואים "חיבור: חי" ו"פורסם".
- קוד שגוי → "הקוד לא נכון".
